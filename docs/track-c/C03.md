# C03 — Syscalls Linux: read, write, openat e erros

## Objetivo

Construir um copiador de arquivos sem libc, em Assembly GNU x86-64, observando a fronteira entre processo e kernel Linux. O código usa `openat`, `read`, `write`, `close` e `exit`.

## Antes de executar (previsão)

- O que `read` devolve no EOF? E em caso de erro?
- Por que `write` pode escrever menos bytes do que foram solicitados?
- Onde o Linux x86-64 coloca o quarto argumento de uma syscall? Compare com chamadas C da ABI System V.
- Por que uma syscall falha retorna um valor negativo em `rax`?

## Execução

Em Linux x86-64, com GNU binutils, make e Python 3:

```sh
make -C labs/low-level/C03 test
make -C labs/low-level/C03 inspect
printf 'exemplo\n' > /tmp/c03-in
labs/low-level/C03/copy /tmp/c03-in /tmp/c03-out
cmp /tmp/c03-in /tmp/c03-out
```

Opcionalmente, se houver `strace`:

```sh
strace -e trace=openat,read,write,close,exit labs/low-level/C03/copy /tmp/c03-in /tmp/c03-out
```

## Quebra controlada

Execute com arquivo de entrada inexistente e depois com diretório de destino inexistente. Registre o exit code e o stderr; compare com a hipótese inicial. Teste também arquivo vazio e arquivo maior que 4096 bytes. Os testes automatizados cobrem esses cenários.

## Limitações e discussão

- Os erros são tratados por código de saída e mensagem genérica, não por tradução de `errno`.
- A implementação demonstra tratamento de escrita parcial, mas não faz retry de `EINTR` e não é uma alternativa robusta ao `cp` do sistema.
- Copiar o mesmo caminho como entrada e saída pode truncar a origem; use somente arquivos descartáveis.
- O destino é criado com modo solicitado 0644, sujeito a `umask`.
- A Trilha B implementa sua própria interface de syscalls; não pressupor números ou ABI Linux compatíveis.
