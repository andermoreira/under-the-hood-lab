# C01 — Do Assembly ao syscall

**Pergunta:** o que acontece entre uma instrução `syscall` e a saída no terminal?

## Objetivos

Identificar registradores usados na ABI de syscall Linux x86-64, montar/linkar um ELF, inspecionar instruções e diferenciar código de usuário de serviços do kernel.

## Previsão (Gate LEARN)

Antes de executar, escreva: qual registrador contém o número da syscall? Onde estão os três primeiros argumentos? Por que `write` pode retornar menos bytes do que solicitamos? O que aconteceria se `exit` recebesse 7?

## Implementação

`hello.s` define `_start` sem libc. Em Linux x86-64, `rax=1` seleciona `write`, `rdi=1` indica stdout, `rsi` aponta para bytes e `rdx` informa comprimento. `rax=60` seleciona `exit` e `rdi` recebe o status. Convenção de syscall Linux não é a mesma coisa que a convenção de chamada de funções System V AMD64.

```sh
make -C labs/low-level/C01 test
make -C labs/low-level/C01 inspect
```

Para observar `write` e `exit`, execute `strace ./labs/low-level/C01/hello` se instalado. Para depurar: `gdb ./labs/low-level/C01/hello`, `break _start`, `run`, `info registers`, `si`.

## Falha controlada

Altere temporariamente `mov $0, %rdi` antes de `exit` para `mov $7, %rdi`, reconstrua e confira `echo $?`. Reverta a alteração. Não execute como root.

## Critérios

- `make test` retorna 0 no Linux x86-64 e valida bytes exatos de stdout e exit code.
- `readelf -h` indica ELF64 x86-64; `objdump -d` mostra `syscall`.
- O diário registra previsão, resultado, divergência e ligação com B08/B09.
- Não marque LEARN como PASS só porque os testes técnicos passaram.

## Limites

Este programa depende da ABI Linux e não roda diretamente na CPU Hack ou no kernel da Trilha B. O exemplo usa `write` de poucos bytes e não implementa retry de escritas parciais; isso será explorado em C03/C08.
