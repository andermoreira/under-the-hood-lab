# C04 — Pequenos coreutils em Assembly

**Objetivo:** construir três utilitários deliberadamente reduzidos em Assembly GNU x86-64, sem libc.

- `echo`: imprime argumentos separados por espaços e termina com newline; não implementa opções `-n`, escapes ou semântica completa do GNU echo.
- `cat`: copia **stdin para stdout**, com buffer de 4096 bytes e tratamento de escrita parcial; não aceita caminhos.
- `wc`: conta **newlines e bytes** de stdin, não palavras, caracteres Unicode ou linhas lógicas sem terminador.

## Preveja antes de executar

1. Quantos `read` serão necessários para 10 KiB de entrada?
2. Por que `write` pode devolver menos bytes que o solicitado?
3. O que `wc` imprime para um arquivo com três caracteres sem newline?
4. Qual é a diferença entre byte, caractere UTF-8 e newline?

## Experimente

```sh
make -C labs/low-level/C04 test
labs/low-level/C04/echo ola mundo
printf 'a\nb\n' | labs/low-level/C04/cat
printf 'a\nb\n' | labs/low-level/C04/wc
make -C labs/low-level/C04 inspect
```

**Falha controlada:** execute `cat arquivo.txt` e explique por que falha; compare `wc` com o GNU `wc -lc` em texto UTF-8. Use dados descartáveis. Para observar syscalls, execute `strace -e read,write,exit` (opcional).

## Contrato de evidências

ENG: saída, exit code, casos binários, múltiplos buffers e argumentos inválidos verificados por teste. LEARN: hipóteses e observações do estudante, incluindo diferenças para coreutils reais. Relacione `read/write` ao laboratório C03 e às interfaces de I/O do kernel da Trilha B, **sem supor compatibilidade de ABI**.

**Limites conhecidos:** `echo` trata uma escrita curta como erro em vez de tentar completar; `cat` não reinicia em `EINTR`; o `wc` conta newline, não linhas sem `\\n`. Não são substitutos para utilitários de produção.
