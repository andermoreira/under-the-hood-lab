# C06 — Stack, heap e memória virtual com mmap

**Objetivo:** observar endereços de objetos na stack, segmentos de dados/BSS, heap e mapeamento anônimo. A aplicação em C usa `malloc`, `mmap`, `munmap` e `sysconf`.

## Previsão

- Em quais regiões você espera encontrar uma variável local, um array estático zerado e um bloco de `malloc`?
- `malloc` sempre usa `brk`? (Não; a estratégia depende do alocador e tamanho.)
- Os endereços serão iguais em duas execuções com ASLR?
- Por que `mmap` devolve `MAP_FAILED` e não necessariamente `NULL`?

## Execução

```sh
make -C labs/low-level/C06 test
make -C labs/low-level/C06 inspect
labs/low-level/C06/memory
```

Compare as regiões com `cat /proc/<pid>/maps` **enquanto o processo estiver vivo** (por exemplo, em um depurador). O programa de demonstração termina rapidamente; o arquivo `maps` não estará disponível após a saída. Use GDB para parar antes de `munmap`.

## Falha controlada

Em uma cópia descartável, tente `mmap` com comprimento zero e registre o retorno e `errno`. Não modifique a aplicação principal nem suponha que os endereços físicos sejam visíveis em `/proc/<pid>/maps`.

## Limites e ponte com a Trilha B

Endereços impressos são **virtuais**, não físicos. O exemplo não implementa page tables ou page faults; compare a observação com os componentes de memória virtual da Trilha B. `malloc` é uma API da libc; `mmap` é invocado via wrapper libc neste laboratório.
